## Phase 3.5 Plan — REST API (interim phase)

Goal: replace the CLI with a FastAPI service; all domain models become pydantic models. One step at a time:

1. **Catalog models to pydantic** — `BaseStats`, `Pokemon`, `Move` as frozen, strict pydantic models.
2. **FastAPI foundation + catalog endpoints** — app factory, settings, catalog dependency, error → HTTP mapping, `GET /pokemon/{id}`, `/moves/{id}`, `/pokemon/{id}/learnset`, `/pokemon`, health, OpenAPI.
3. **Deterministic endpoints** — teams, battlers, battle engine state and results to pydantic (engine slowdown measured); `POST /teams/analysis`, `/battlers`, `/damage`, `/battles` (code players).
4. **Single-call agent endpoints** — agent outputs to pydantic (schemas generated from models); `/research`, `/teams/build`, `/teams/optimize`, `/advise`, `/scout`.
5. **Background jobs** — job store and runner for agent battles and evaluation suites; `POST /jobs/…`, `GET /jobs/{id}`.
6. **Remove the CLI** — port remaining CLI tests to API tests; README and docs.

## Completed

### Phase 3.5 — REST API (branch `phase-3.5`)

Deliverable: a FastAPI service that replaces the CLI. Every domain model, battle-engine type and agent output is a frozen, strict pydantic model; the OpenAPI schema, the request validation and the LLM output schemas are all generated from them. Lookups and deterministic work (catalog, team analysis, battlers, damage, single battles) are synchronous endpoints; each agent has a synchronous endpoint returning its result plus observed token usage; agent battles, multi-run battles and the four evaluation suites run as background jobs (`POST /jobs/...` → 202, `GET /jobs/{id}`). PokéAPI became the source of truth for every catalog read (D48).

### Phase 3 — Battle Intelligence (branch `phase-3`)

Deliverable: an AI-assisted battle strategy system. A deterministic, seeded battle engine (catalog stats, moves and learnsets; the Gen 6+ damage formula) plays teams against each other; `pokeverse battle --player1 agent` lets a Battle Strategy Agent choose actions from code-computed facts, briefed by an Opponent Analysis Agent whose counters are verified by code; `pokeverse battle-eval` and `battle-feedback` measure win rates with confidence intervals, detect mistakes deterministically and test lessons from a Battle Evaluation Agent on unseen seeds.

### Phase 2 — Multi-Agent Trainer System (branch `phase-2`)

Deliverable: a multi-agent Pokémon team advisor. `pokeverse advise` routes any request through a Supervisor to the Research, Team Composition and Team Optimization agents, hands verified facts between them, and re-checks every team and type claim with deterministic code; `pokeverse compare` measures it against a single-agent baseline.

### Phase 1 — Intelligent Pokédex (branch `phase-1`)

Deliverable: a CLI-based intelligent Pokédex. `pokeverse research` answers Pokémon questions with a tool-using, structured-output agent grounded in a local, outage-tolerant catalog; `pokeverse eval` measures it.

## Phase 3 Plan (proposed; revise as we learn)

Deliverable: an AI-assisted battle strategy system. Battle mechanics are deterministic code; agents only choose actions and explain them. Mechanics are deliberately simplified singles: no abilities, items, status conditions or weather; every Pokémon at level 50 with fixed IVs/EVs and a neutral nature.

1. **Base stats in the catalog** — the numbers battles need (HP, attack, defense, special attack, special defense, speed).
2. **Moves as reference data** — `Move` (type, physical/special/status, power, accuracy, priority, PP) imported from PokéAPI into the catalog.
3. **Learnsets and battle movesets** — the moves each Pokémon can learn, stored with the catalog, and a battler of up to 4 moves validated against it.
4. **Battle stats and damage** — level-50 stat formula and the damage formula (STAB, type effectiveness, critical hits, random roll) as pure functions with an injectable RNG.
5. **Battle engine** — immutable battle state, legal actions (move or switch), turn order (priority, then speed), fainting and forced switches; seeded, reproducible battle logs.
6. **Baseline players and `pokeverse battle`** — a deterministic default moveset (ranked with the damage formula), random and greedy (highest expected damage) players; simulate team vs team from the CLI.
7. **Battle Strategy Agent** — an LLM picks actions with tools (legal actions, damage estimates); code validates every choice.
8. **Opponent Analysis Agent** — threat assessment of an opposing team from deterministic matchups and damage ranges, handed to the strategy agent as verified facts.
9. **Battle evaluation and feedback** — many seeded battles: agent vs greedy win rate and cost; a Battle Evaluation Agent reviews logs for mistakes, and its feedback is fed into the next run and measured.

CLI: `pokeverse learnset <pokemon> [--json] [--offline]` and `pokeverse moveset <pokemon> <move>... [--json] [--offline]` (exit 2 for invalid movesets). The default moveset moved to Step 6, where the damage formula can rank moves. Known limit: Pokémon with no damaging moves (e.g. Ditto, Transform only) cannot battle.

- [x] Step 4: battle stats and damage — `battle_stats(base)` gives level-50 stats (31 IVs, 0 EVs, neutral nature; base HP 1 stays 1, as for Shedinja). The Gen 6+ damage formula follows Pokémon Showdown's integer order: base damage, critical hit ×1.5 (1 in 24, Gen 7+), random roll 85–100%, STAB ×1.5 rounded half down, type effectiveness as repeated doubling/halving, minimum 1 unless immune. `calculate_damage` (explicit roll and critical), `damage_range` (min/max without a critical hit) and `roll_damage` (draws from an injected `random.Random`, so seeded results are reproducible) return plain numbers; accuracy is left to the engine (Step 5). Expected values in tests are hand-computed from the algorithm; stats match published level-50 figures (Garchomp 183/150/115/100/105/122). `pokeverse damage <attacker> <move> <defender> [--json] [--offline]` shows the range, % of the defender's HP, effectiveness, STAB and the critical-hit maximum. Not cross-checked against Smogon's calculator (Node is not installed).

- [x] Step 5: battle engine — `pokeverse.battles.engine`, pure state transitions over immutable `BattleState` → `Side` → `Combatant` (battler + current HP). Actions are `UseMove(index)` or `Switch(index)`; `legal_actions` lists them (only switches after a faint, nothing once the battle is over), and every choice is checked against it (`IllegalActionError`) — the hook for validating agent choices later. `play_turn` resolves switches first, then moves by priority, speed and a random tie-break; type immunity is checked before the accuracy roll (Showdown's order); a battler knocked out earlier in the turn does not act. `replace_fainted` handles forced switches. `run_battle` drives two `Player`s (a one-method protocol) until a side is defeated or `MAX_TURNS` (100) is reached (draw), and returns structured `BattleEvent`s (`to_dict`, `describe`) for later analysis. Same seed, same battle. Simplifications: PP is not tracked (so no Struggle); the turn cap prevents endless mutual-immunity battles. Observed: a naive first-option player keeps using Earthquake on an immune Charizard and loses — the baseline Step 6 improves on.

- [x] Step 6: baseline players and `pokeverse battle` — default movesets (`pokeverse.battles.movesets`): `move_score` = power × accuracy × STAB × matching attack stat; `choose_moveset` takes the best-scoring move, then the best that add super-effective coverage (one move per type); `default_battler` needs every learnable move (~100 PokéAPI requests the first time per Pokémon, ~4 s; cached afterwards, so offline works). `is_battle_move` / `UNMODELLED_MOVES` exclude moves whose drawback or special rule the engine does not model (self-KO, recharge, charge turn, conditional, HP-scaled power, self-damage, non-standard attack stat); `Battler` rejects them too. PokéAPI quirks fixed at ingestion: `0` power/accuracy means "none" and status moves never have power (found on Dragon Cheer). Players (`pokeverse.battles.players`): `RandomPlayer` and `GreedyPlayer` (highest expected damage = average roll × accuracy, capped at the foe's HP; priority breaks ties; switches only when no move can hurt; replaces with the best attacker). `pokeverse battle --side1 … --side2 … [--player1/2 greedy|random] [--seed] [--runs] [--json] [--offline]` (members `name` or `name:move,move`); `pokeverse moveset <pokemon>` without moves shows the default. Results (Garchomp/Pikachu/Charizard mirror, 50 seeds): greedy beat random 43–7 and 48–2. Greedy vs greedy was 18–32 over 50 seeds but 481–519 over 1,000 — no side bias; 50 battles are too few to compare win rates. Known limits: lock-in moves (Outrage) look free because confusion is not modelled; default movesets are opponent-independent.

- [x] Step 7: Battle Strategy Agent — `BattleStrategyAgent` (`pokeverse.agents.battle_strategy`) is a battle `Player`: one LLM call per decision with no tools; code writes the facts into the prompt (`describe_situation`: both actives with HP and speed, who moves first, the foe's moves against our active, every legal option with exact damage ranges as % of remaining HP and KO flags, and for each switch the threat it would face and the damage it could deal). The strict output schema is built per decision, with the legal option ids (`move-1:outrage`, `switch-2:pikachu`) as an enum, so the model can only name a legal action; the engine still validates it. A single legal option is taken without a model call. Malformed or refused replies fall back to `GreedyPlayer` and are recorded (`fallback`); auth/outage errors abort. Decisions record turn, option, one-sentence reason and tokens. `pokeverse battle --player1 agent` prints the agent's decisions and token use. Live (gpt-5.6-terra, effort low), seed 1, Garchomp/Pikachu/Charizard vs Tyranitar/Gyarados/Snorlax: greedy lost this battle in Step 6, the agent won it — it chose the guaranteed Earthquake KO over Outrage on turn 2 and Focus Blast to set up the Snorlax KO; 9 decisions, 7.4k tokens, 0 fallbacks. One battle is an anecdote; win rates are Step 9.

- [x] Step 8: Opponent Analysis Agent — deterministic matchups (`pokeverse.battles.matchups`): for every pair, each side's best move, damage range, who moves first, hits to KO with minimum rolls, and who wins the full-HP one-on-one. `OpponentAnalysisAgent.analyze(own, foe)` (one LLM call before the battle) reads that table and returns a strict `OpponentAnalysis`: every foe ranked once by danger, counters (which of our members handles which threat; team slots as enums) and a plan. Code checks it: each foe must be ranked exactly once, and a counter is `verified` only if the matchup says our member wins that one-on-one. The briefing handed to the Battle Strategy Agent contains only the threat ranking and verified counters (no free prose, per D31), and is re-rendered from the live state at every decision, dropping knocked-out threats and answers. `pokeverse scout --side1 … --side2 …` prints the report and briefing; `pokeverse battle` briefs agent players by default (`--no-analysis` to compare). Found live: with a briefing rendered once before the battle, the agent switched out Pikachu on turn 5 "to keep it for Gyarados" — which had fainted on turn 4 — and lost the seed-1 battle; the live-state briefing fixed it (regression test added). Also caught in tests: "Pikachu counters Charizard" (super effective) is not verified — Charizard wins that one-on-one (2HKO vs 3HKO). Live sanity check, seeds 1–4 vs greedy (Garchomp/Pikachu/Charizard vs Tyranitar/Gyarados/Snorlax): greedy 0/4, agent without analysis 3/4 (~7.3k tokens per battle), agent with analysis 4/4 (~9.5k incl. ~1.3k for the analysis). Four battles are not evidence; Step 9 measures.

- [x] Step 9: battle evaluation and feedback — `pokeverse.battles.review`: `RecordingPlayer` wraps any player; `judge` flags only clear-cut mistakes from engine facts (`missed_ko`: a guaranteed, can't-miss KO that lands first was available; `no_effect`: an immune target while a damaging move existed; `switched_into_ko`); forced replacements are not judged. `BattleReviewAgent` turns detected mistakes into ≤3 lessons that must cite mistake ids (uncited ones dropped; no mistakes → no call); lessons are appended to the strategy prompt. `pokeverse.evals.battles`: two fixed scenarios against a greedy side 2 (`bulk`, `starters`); per system (`greedy`, `agent`, `agent+analysis`) wins, Wilson 95% intervals, turns, mistakes and tokens per battle, fallbacks; `feedback_experiment` learns on training seeds and tests on disjoint seeds, stopping early when there is nothing to learn. CLI: `battle-eval`, `battle-feedback` (progress on stderr). The detector found two real bugs: in itself (a 70%-accurate Focus Blast KO is not "guaranteed") and in the Step 6 greedy baseline (it capped damage at the foe's HP after weighting by accuracy, so it picked a 90% Overheat over a sure Outrage). Fixed greedy makes 0 detected mistakes and is stronger: greedy-vs-greedy side 1 win rate over 50 seeds fell from 26% to 20% (bulk) and 10% to 0% (starters), so earlier agent comparisons were against a weaker opponent. Live (gpt-5.6-terra, effort low, 5 seeds each, vs corrected greedy): bulk — greedy 1/5 (20%, CI 4–62%), agent 2/5 (40%, 12–77%, 7.7k tokens/battle), agent+analysis 2/5 (40%, 12–77%, 8.7k); starters — all 0/5 (CI 0–43%), agent+analysis 0.2 detected mistakes/battle at 9.8k tokens. The intervals overlap everywhere: no system can be ranked from these samples. `battle-feedback` on bulk: the agent won 4/5 training battles with 0 detected mistakes, so there were no lessons and the test battles were skipped. The same seeds gave the agent 2/5 an hour earlier — model variance on top of game randomness. Conclusion: the agents avoid every clear-cut mistake the detector knows; their losses come from judgement and luck, which this feedback loop cannot learn from yet.
